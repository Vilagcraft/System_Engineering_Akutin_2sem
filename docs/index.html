1. Контекст и границы системы

Миссия

Спроектировать и эксплуатировать высоконадёжную, безопасную и нормативно совместимую платформу для криптовалютной биржи.

  • SLA: торговый API 99.99%, вывод 99.95%
  • Целевая нагрузка: 10 000 RPS на публичный API
  • Latency: p99 < 200 мс для API, p99 < 1 с для HSM-подписи

Границы SoI

Внутри: API Gateway, Matching Engine, Ledger, Wallet Orchestrator, AML Engine, KMS Policy Service, Audit & Forensics, Admin Back Office.

Снаружи: HSM Cluster, BTC/ETH/TRON-ноды, SIEM, KYC-провайдер, фиатные платёжные шлюзы.

5 сценариев

S1. Вывод криптовалюты

2FA → AML → резервирование → HSM-подпись → broadcast → confirmations.

S2. Создание API-ключа

Self-service, scopes trade/withdraw/info, TTL, IP whitelist для withdraw.

S3. Cold storage multisig

Крупный вывод через quorum 2-of-3 и полный audit trail.

S4. Ротация HSM-ключей

Dual control, MFA, проверка подписи, архивирование старого ключа.

S5. Инцидент и отчёт

Поиск по correlation_id, сбор WORM-логов, экспорт PDF/CSV.

ADR

ADR-1: PostgreSQL вместо MongoDB

Выбран ACID и double-entry ledger. Trade-off: меньше гибкости схемы, выше консистентность финансовых данных.

ADR-2: Kafka вместо RabbitMQ

Выбрана replayability, event sourcing и высокая пропускная способность audit-событий.

ADR-3: Kubernetes вместо Nomad

Выбран зрелый ecosystem, autoscaling, network policies и стандартные deployment-практики.
